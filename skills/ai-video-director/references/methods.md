## 1. 科普脚本方法（路线⑥ 首选，① 也适用）

### 1.1 结构：钩子 → 比喻 → 分层解释 → 公式 / 数据 → 一句话总结

| 段落 | 时长（30–60 秒片） | 写法 | deck.md 对应 |
|---|---|---|---|
| 钩子 | 0–3 秒 | 反常识问题（「天空为什么不是紫色？」）、一个具体数字（「蓝光被散射的强度是红光的 6 倍」）、一个看得见的现象 | 封面页 `layout: image-full`，标题 `{build: zoom}`，`==关键词==` 跟着旁白高亮 |
| 比喻 | 5–8 秒 | 用观众熟悉的画面讲直觉：台球碰撞、筛子、排队、水波 | `default` / `image-right`，要点 `{at: 词}` 逐条出现，比喻词 `mark: underline:词` |
| 分层解释 | 每层 5–8 秒 | 现象 → 直觉 → 原理；每层一页，层与层之间 `transition: morph`，用同一个 `id` 把标题 / 公式带到下一页 | `{id: q}` + `transition: morph` |
| 公式 / 数据 | 5–8 秒 | 公式只留核心一行，`\term{}` 标出要点亮的项，边念边圈；数据用柱状 / 折线，按讲解顺序升起 | `layout: formula` + `terms: [...]`；`layout: chart` + 每根柱子 `at:` |
| 总结 | 3–5 秒 | 回到开头的问题，一句可复述的结论（或 3 个关键词） | `layout: end` |

### 1.2 页面规则

- **一页一个想法**，标题就是结论句（「短波长更容易被散射」，而不是「散射」）。竖屏标题 ≤18 字，横屏 ≤24 字。
- **要点 ≤4 条**，每条 ≤22 字（竖屏）；每条在旁白说到关键词时出现（`{at: 词}`，不写则自动在旁白里找要点文字）。
- **每 3–5 秒画面要有新变化**：要点出现、圈注、高亮、图表升起、聚光灯、变形。`lint` 会报告最长静止时长（>6 秒警告）。
- **类比先于公式**：先让观众「看见」，再给符号。
- **图是示意**：ChatGPT 出图用 `prompts` 命令生成的中文提示词（已要求画面不含文字），文字永远由视频叠加，保证清晰、可改。

### 1.3 旁白与字幕节奏

- 一句 `> say:` = 一条字幕 = 一口气能读完（竖屏一行约 12–16 字，最多两行）。
- 中文 4–5.5 字/秒（Kokoro 默认语速约 4 字/秒，`speed: 1.1` 左右更像短视频）；按每分钟约 280 字估时长。（脚本验收思路：[video-podcast-maker](https://github.com/Agents365-ai/video-podcast-maker) MIT）
- 数字、单位、英文、专有名词单独校对（TTS 误读大多出在这里）：「450nm」写成「四百五十纳米」，「1871 年」写成「一八七一年」；`at:` 要写旁白里实际出现的字。
- 关键词与画面同时出现：`at` 绑定的是该词**开始说出**的时刻，`.end` 绑定说完的时刻。

### 1.4 deck.md 速写模板

```markdown
---
title: 为什么天空是蓝色的？
aspect: "9:16"
theme: tianji
speed: 1.1
---
layout: image-full
image: 01.png
---

# 为什么天空是==蓝色==的？ {build: zoom}

> say: 天空为什么是蓝色的？答案在一个公式里。

---
layout: formula
transition: morph
---

# 瑞利散射 {id: q}

$$ I \propto \frac{1}{\term{\lambda^4}} $$ {terms: ["四次方"]}

> say: 散射强度和波长的四次方成反比。
```

完整样片：`slides2video/examples/sky/deck.md`（约 34 秒）。语法：`slides2video/README.md`。MCP：`get_slides_plan`（给题目起骨架 / 检查 deck）。

## 2. 其他题材的台词要点（摘要）

| 题材 | 结构 | 路线 |
|---|---|---|
| 仓库推荐（天机） | 它能帮你做什么 → 可信信号（许可、star、谁在用）→ 三步上手 → 适合谁 → 天机亮扇揭晓项目名 | ① + ③ 插段（或 ⑥ 做功能对比页） |
| 知识口播 | 反常识结论 → 比喻 → 两个原因 → 马上能做的方法 → 总结 | ①（或 ⑥） |
| 拆书 | 这本书解决什么问题 → 3 个观点各配一个画面化例子 → 一句可执行建议；不朗读原文大段 | ① / ⑥ |
| 数据故事 | 最惊人的数字 → 趋势图 → 对比 / 排名 → 这意味着什么（注明来源） | ③ / ⑥ |
| 绘本 | 从前… → 遇到难题 → 失败一次 → 换办法 / 朋友帮忙 → 成功并明白道理；语速 0.9× | ① |
| 诗词 | 题签逐字写出 → 一句诗一个画面 → 白话说一句诗意；译文赏析自写 | ①（水墨） |
| 产品带货 | 0–3 秒痛点 / 对比 → 卖点 1 → 卖点 2/3 + 证据 → 场景 + 行动号召；不用绝对化用语 | ② / ③ |
| 短剧 | 3 秒立冲突 → 升级 → 反转 / 爽点 → 留钩子 | ②（free-cpu 漫剧先 ①） |

## 3. 各路线吸收的强项（怎么用在你的片子里）

- **字幕事件驱动画面**（srt-whiteboard-animation 思路）：①的 `"at": "c3:苹果树"`、⑥的 `{at: "c3:散射"}` 是同一套时间引用语法，能互相迁移脚本。
- **同 id 跨页变形**（reveal.js Auto-Animate 思路）：⑥的 `transition: morph`，适合「同一个公式被展开」「同一个标题换说法」。
- **手绘标注**（rough-notation 思路）：⑥的 `mark: circle|underline|highlight|box|strike`，圈出旁白正在说的词。
- **PPT 备注即旁白**（pptx2video 协议）：已有 PPT 时 `slides2video import 课件.pptx`，备注里 `## [handle]` 对应形状的替代文字 `[handle]`，`[[Spotlight] …]` 变成聚光框。
- **huashu 转场**：①⑤⑥ 共用 `animator/vendor/huashu-art-motion` 的 50 种转场（⑥ 写 `transition: huashu:godRays`）。
- **静图视差**（DepthFlow / kburns 思路）：⑤；⑥ 的整页配图自带缓慢推近。
